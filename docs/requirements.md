# 需求说明（阶段 5a）

本文档记录对 `external/task.md` 的理解，以及与用户确认过的决定。

## 1. 平台

| 项目 | 决定 |
|---|---|
| 语言 | Python 3.12（服务端），浏览器端为原生 HTML/JS（无构建步骤） |
| 依赖 | 安装在项目目录下的 `.venv`（`aiohttp`，测试用 `pytest`） |
| 监听地址 | `--listen IP` > 环境变量 `$ZEROTIER_IP` > `127.0.0.1`；端口 `--port`，默认 8000 |
| 登录 | 输入用户名；首次登录可设置密码（视为注册），密码可留空。同名再次登录 = 重连，接管原座位 |
| 会话 | 服务端签发 token，浏览器保存，刷新页面后自动重连 |
| 界面语言 | 中文 |

## 2. 房间

- 房号：4 位大写字母，创建时随机生成。
- 创建者为房主。房主可以：把空座位设为 AI、移除座位上的玩家/AI、开始游戏、回退、导出/导入 JSON、重新开始、关闭房间。
- 其他用户凭房号加入，自动坐到空座位；没有空座位则旁观（只看公开信息）。
- 多个房间可同时进行；同一用户可以在多个房间里有座位。
- 玩家掉线：座位保留，等待重连；房主可把该座位交给 AI。
- 服务器重启后，房间及其状态从磁盘（`data/`）恢复。

## 3. 统一底层

- 所有游戏共享同一套状态结构：牌（静态属性）、牌区（带所有者和可见性）、公开变量、每个座位的私有变量、随机数状态、日志。
- 规则模块只需实现：初始化、当前谁需要做什么决定（可多人同时）、应用动作并校验合法性。
- 状态完整可序列化为 JSON：导出、导入、回退都基于它。随机数状态也在 JSON 内，回退后结果可复现。
- 信息遮蔽从第一版起实现：服务端持有全知状态，发给每个座位的是遮蔽后的视图（其他人的手牌只显示张数，不含牌的 id）。
- 回退：房主可回到任意历史状态，不对回退造成的信息泄露做特殊处理。

## 4. 红心大战（与 Windows XP 版相同）

- 4 人，人数不足由 AI 补齐（AI 默认名 Pauline、Michele、Ben）。
- 每局发 13 张，传 3 张牌，方向按 左 → 右 → 对家 → 不传 循环。
- 持 2♣ 者首先出 2♣。
- 必须跟花色；第一墩不能出分牌（红心、Q♠），除非手里全是红心或 12 张红心加 Q♠（此时可出红心）。
- 红心被打出后才算“破”；Q♠ 不破红心。红心未破时不能首出红心，除非手里只剩红心。
- 红心每张 1 分，Q♠ 13 分。一人拿到全部 26 分（射月）则自己 0 分、其他三人各 26 分。
- 有人累计 ≥ 100 分时游戏结束，分最低者胜（可并列）。
- 每局结束显示计分表（含历史），所有人确认后进入下一局。
- AI：一个难度，行为模仿 XP 电脑玩家（XP 源码未公开，采用启发式实现，只使用该座位可见的信息，不作弊）。

## 5. 城市交易所

规则细节（货币下限、兑现是否触发点炮、出游是否循环、斗地主/角色范围等）由用户后续再定。
底层需要预留：每次弃牌后其他玩家的响应窗口（点炮）、多人同时决策、技能钩子。

## 6. 流程

- git：`dev` 分支开发，每个阶段完成后 `--no-ff` 合并到 `master`。不修改 `external/`。
- 完成 5d（红心大战 AI）后停下，启动服务器给用户测试。
